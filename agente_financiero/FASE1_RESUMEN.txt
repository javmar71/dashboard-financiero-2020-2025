--- CONSTRUCCIÓN DEL JSON SCHEMA (DISEÑO, NO IMPLEMENTACIÓN) ---

El schema JSON fue diseñado conceptualmente (no como archivo .py recién creado) basándose en:

1. Estructura anidada: documento → estados_financieros[] → metadata_estado → columnas[] → registros[]
   - Esto permite múltiples estados financieros (Balance, Resultados, Flujos) dentro de un mismo PDF

2. Cada registro conserva separadamente:
   - valor_original: "5.000.000" (tal como aparece en PDF)
   - unidad_original: "Miles" o el símbolo "$"
   - factor_conversion: 1000 (si de miles a unidades base) o 1 (si ya en unidades base)
   - valor_normalizado: 5000000.0 (en unidades base del proyecto)
   - unidad_normalizada: "COP" (o la moneda base del proyecto)
   - evidencia_unidad: "Encabezado de tabla: 'Pesos Colombianos en Miles'"

3. Estructura de periodos (NUNCA se inventan):
   - documento.ano: 2021 (del nombre del archivo por convención Fase 0A)
   - estado.periodo_principal: "2025" (identificado del documento)
   - estado.periodo_comparativo: "2024" (si existe evidencia)
   - registro.periodo: "2025" o "2024" (según el dato específico)
   - Si no se puede determinar: periodo = null (NUNCA se asigna un valor falso)
   - El año del documento y el periodo contable son variables distintas

4. Consolidadado/separado (politica estricta):
   - es_consolidado = null cuando no haya evidencia
   - true SOLO cuando haya evidencia documentada de consolidado
   - false SOLO cuando haya evidencia documentada de estado separado
   - Nunca se asume false por ausencia de evidencia

5. Evidencia estructurada (cadena rastreable):
   INDICADOR -> VARIABLE MADRE -> CUENTA -> VALOR -> PERIODO -> PAGINA -> PDF
   - archivo: nombre del PDF
   - pagina: número de página o null si desconocido (NUNCA 1 por defecto)
   - estado_financiero: "Balance General", "Estado de Resultados", etc.
   - periodo: "2025", "2024", etc. o null
   - cuenta_original: tal como aparece en el documento
   - contexto_tabla: "Balance General", fila X, columna Y
   - texto_encabezado: fragmento de texto del encabezado
   - unidad: "Miles", "Millones", "$", etc. o null
   - metodo_extraccion: "gemini", "regex", "ocr", "híbrido"
   - region: región de la página si puede identificarse

6. Modelo de confianza (5 dimensiones separadas, no un solo score):
   - conf_lectura: confianza en la lectura del documento
   - conf_identificacion: confianza en la identificación de cuenta
   - conf_unidad: confianza en la unidad monetaria
   - conf_periodo: confianza en el periodo asignado
   - conf_puc: confianza en la asignación del código PUC
   - Cada uno en escala: ALTA / MEDIA / BAJA / NO_DETERMINADA
   - Nunca un solo número combinado

7. Jerarquía de fallback (por campo, no por documento completo):
   - Nivel 1: JSON de Gemini (preferente)
   - Nivel 2: Texto nativo + regex cuando hay deficiencia concreta
   - Nivel 3: OCR Tesseract SOLO cuando sea realmente necesario
   - Nivel 4: Revisión humana
   - Nunca se salta un nivel sin antes agotar la razón para hacerlo

8. Asignación PUC (sin inventar):
   - Gemini sugiere codigo_puc_sugerido basándose en nombre de cuenta
   - Python valida contra la taxonomía PUC existente (21 cuentas de puc.ipynb)
   - Si existe coincidencia única: asignar codigo_puc con estado ASIGNADO
   - Si múltiples coincidencias plausibles: codigo_puc = null, estado_puc = AMBIGUO
   - Si no hay coincidencia: codigo_puc = null, estado_puc = SIN_MAPEO
   - Python NUNCA crea códigos PUC nuevos

9. Mapeo a variables madre (sin crear automáticamente):
   - Python busca en la taxonomía existente (de FASE6 o definida en proyecto)
   - Coincidencia exacta por nombre canonical: ASIGNADO
   - Similitud semántica con validaación empírica (no umbrales arbitrarios como 0.85): ASIGNADO con anotación
   - Sin correspondencia suficiente: variable_madre = null, estado = SIN_MAPEO o AMBIGUO
   - Python NUNCA crea nuevas variables madre automáticamente
   - Nueva variable madre solo mediante decisión humana y modificación controlada de taxonomía

10. Fallback por campo (no documento completo):
    - Ejemplo: Gemini encuentra cuenta y valor. Regex encuentra unidad.
    - cuenta = Gemini, valor = Gemini, unidad = Regex
    - La procedencia queda registrada por campo en el JSON
    - La validación Python decide el estado final basado en la combinación de fuentes
