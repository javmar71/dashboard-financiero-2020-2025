================================================================
13. FALLBACK POR CAMPO
================================================================

Jerarquía técnica definida y documentada:

Nivel 1: JSON de Gemini (preferente - siempre que JSON válido con campos mínimos)
Nivel 2: Texto nativo + regex cuando hay deficiencia concreta (ej: Gemini falta unidad pero regex la encuentra)
Nivel 3: OCR Tesseract SOLO cuando realmente sea necesario (PDF sin texto seleccionable)
Nivel 4: Revisión humana (último recurso)

Nunca se ejecuta OCR simplemente porque exista. El fallback se activa por deficiencias concretas identificadas en la validación JSON.

Ejemplo operativo:
- Gemini encuentra cuenta y valor -> JSON generado
- Validación detecta unidad_original null -> Se intenta regex fallback SOLO para ese campo
- Si regex encuentra unidad -> se adiciona al JSON con evidencia "regex_fallback"
- Si regex falla -> unidad_original null, estado NO_DETERMINADA
